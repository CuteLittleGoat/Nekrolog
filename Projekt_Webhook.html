Cel

Jaki efekt chcemy osiągnąć

Aplikacja Nekrolog ma nadal działać jako statyczna strona na GitHub Pages. Frontend strony ma tylko wyświetlać dane z plików JSON. Nie wolno umieszczać w nim sekretów, tokenów ani adresu webhooka Discorda.

Nowy mechanizm ma działać podczas odświeżania danych, czyli po stronie skryptu scripts/refresh_static.mjs. Gdy skrypt znajdzie wpis pasujący do osoby Helena Gawin, w dowolnym z obecnie obsługiwanych wariantów zapisu, ma wysłać wiadomość na wybrany kanał Discorda przez webhook.

Najważniejszy efekt końcowy: jeśli w aktualnych wynikach aplikacji pojawi się nowe trafienie dla Heleny Gawin, Discord dostanie jedną wiadomość na wskazanym kanale.
Ważne: wiadomość nie może wysyłać się bez końca przy każdym kolejnym odświeżeniu. Trzeba zapisywać informację, które trafienia zostały już zgłoszone na Discordzie.

Treść docelowej wiadomości zostanie ustalona później. Na razie Codex ma przygotować bezpieczny, prosty placeholder, który będzie można łatwo zmienić w jednej funkcji.

Część 1

Instrukcja dla użytkownika: co przygotować przed pracą Codex

1. Co musisz mieć przed rozpoczęciem

  • Dostęp do Discorda.
  • Serwer Discord, na którym masz uprawnienie do zarządzania webhookami albo jesteś administratorem.
  • Wybrany konkretny kanał Discord, na który mają przychodzić powiadomienia.
  • Dostęp do repozytorium GitHub: CuteLittleGoat/Nekrolog.
  • Możliwość wejścia w zakładkę Settings w repozytorium GitHub.
Nie wklejaj adresu webhooka do plików aplikacji. Webhook Discorda działa jak tajny klucz. Kto ma ten adres, może publikować wiadomości na wybranym kanale. Adres webhooka wolno wkleić tylko do sekretu GitHub Actions.

2. Przygotowanie webhooka na Discordzie

Webhook jest przypisany do konkretnego kanału. To znaczy, że jeżeli utworzysz webhook w kanale #nekrologi, wiadomości będą trafiały właśnie tam.

Wariant A — przez ustawienia konkretnego kanału

  1. Otwórz Discorda.
  2. Wejdź na serwer, na którym ma pojawiać się powiadomienie.
  3. Na liście kanałów po lewej stronie znajdź kanał, na który mają przychodzić wiadomości, na przykład #nekrologi, #powiadomienia albo inny wybrany kanał.
  4. Najedź myszką na nazwę kanału. Obok nazwy powinno pojawić się małe kółko zębate. Kliknij to kółko zębate. To jest opcja Edit Channel / Edytuj kanał.
  5. W menu po lewej stronie poszukaj pozycji Integrations / Integracje. Kliknij ją.
  6. Znajdź sekcję Webhooks.
  7. Kliknij New Webhook, Create Webhook albo podobny przycisk. Nazwa przycisku może się minimalnie różnić zależnie od wersji Discorda.
  8. Nadaj webhookowi prostą nazwę, na przykład:
    Nekrolog
    albo:
    Nekrolog Monitor
  9. Sprawdź, czy jako kanał webhooka wybrany jest właściwy kanał. Jeśli nie, wybierz właściwy kanał z listy.
  10. Kliknij Copy Webhook URL / Kopiuj adres webhooka.
  11. Na razie nie wysyłaj tego adresu nikomu i nie zapisuj go w publicznym pliku. Za chwilę wkleisz go bezpośrednio do sekretu w GitHubie.
  12. Jeśli Discord pokazuje przycisk Save Changes / Zapisz zmiany, kliknij go.

Wariant B — przez ustawienia serwera

  1. Otwórz Discorda i wejdź na właściwy serwer.
  2. Kliknij nazwę serwera w lewym górnym rogu.
  3. Wybierz Server Settings / Ustawienia serwera.
  4. W menu po lewej stronie kliknij Integrations / Integracje.
  5. Wejdź w sekcję Webhooks.
  6. Kliknij New Webhook / Create Webhook.
  7. Ustaw nazwę webhooka, na przykład Nekrolog.
  8. Wybierz kanał, na który webhook ma pisać.
  9. Kliknij Copy Webhook URL.
  10. Jeśli trzeba, kliknij Save Changes.
Jeśli nie widzisz opcji Webhooks: prawdopodobnie nie masz wymaganych uprawnień na serwerze lub kanale. Poproś właściciela serwera albo administratora o nadanie uprawnienia Manage Webhooks / Zarządzanie webhookami, albo poproś go o utworzenie webhooka i przekazanie Ci adresu.

3. Dodanie webhooka jako sekret w GitHubie

Teraz trzeba wkleić adres webhooka do GitHuba jako sekret. Dzięki temu skrypt uruchamiany przez GitHub Actions będzie mógł wysłać wiadomość na Discorda, ale adres webhooka nie pojawi się w publicznym kodzie strony.

  1. Otwórz przeglądarkę i wejdź na GitHub.
  2. Zaloguj się na konto, które ma dostęp do repozytorium.
  3. Wejdź do repozytorium:
    CuteLittleGoat/Nekrolog
  4. Na górze strony repozytorium znajdź zakładkę Settings. Kliknij ją.
  5. Jeśli nie widzisz zakładki Settings, możliwe, że nie masz odpowiednich uprawnień. W takim przypadku trzeba wejść z konta właściciela repozytorium albo poprosić właściciela o wykonanie tej części.
  6. W menu po lewej stronie znajdź sekcję Security.
  7. Kliknij Secrets and variables.
  8. Kliknij Actions.
  9. Upewnij się, że jesteś w zakładce Secrets, a nie Variables.
  10. Kliknij przycisk New repository secret.
  11. W polu Name wpisz dokładnie:
    DISCORD_WEBHOOK_URL
  12. W polu Secret wklej adres webhooka skopiowany z Discorda.
  13. Kliknij Add secret.
Po zapisaniu sekretu GitHub pokaże jego nazwę, ale nie pokaże już jego wartości. To normalne i prawidłowe. Jeśli kiedyś zgubisz adres webhooka, najprościej utworzyć nowy webhook na Discordzie albo skopiować go ponownie z ustawień Discorda i nadpisać sekret w GitHubie.

4. Czego nie robić

  • Nie wklejaj adresu webhooka do app.js.
  • Nie wklejaj adresu webhooka do index.html.
  • Nie wklejaj adresu webhooka do README.md.
  • Nie wklejaj adresu webhooka do rozmowy publicznej ani do issue/pull requesta.
  • Nie zapisuj adresu webhooka w data/latest.json, data/job.json ani data/errors.json.

5. Co przekazać Codexowi

Po przygotowaniu webhooka i sekretu możesz przekazać Codexowi ten plik HTML oraz polecenie: 

W repozytorium CuteLittleGoat/Nekrolog zaimplementuj powiadomienie Discord zgodnie z plikiem Nekrolog_Discord_Webhook_Instrukcja_Codex.html. Webhook jest już zapisany jako GitHub Actions secret DISCORD_WEBHOOK_URL. Nie ujawniaj sekretu w kodzie ani w logach.

6. Jak sprawdzić po wdrożeniu

  1. Po zmianach Codexa wejdź w repozytorium GitHub.
  2. Kliknij zakładkę Actions.
  3. Wybierz workflow odpowiedzialny za odświeżanie danych.
  4. Kliknij Run workflow, jeśli workflow ma możliwość ręcznego uruchomienia.
  5. Poczekaj, aż workflow zakończy się zielonym statusem.
  6. Wejdź na wybrany kanał Discorda i sprawdź, czy pojawiła się wiadomość, jeśli w danych jest nowe trafienie dla Heleny Gawin.
  7. Uruchom workflow drugi raz. Jeśli nie pojawiło się nowe trafienie, wiadomość nie powinna wysłać się ponownie.
Jeśli w danym momencie aplikacja nie znajduje Heleny Gawin, brak wiadomości na Discordzie jest normalny. Sam brak wiadomości nie oznacza jeszcze błędu. Błąd byłby wtedy, gdy aplikacja ma nowe trafienie, a mimo poprawnego sekretu i działania workflow wiadomość się nie wysyła.
Część 2

Informacja techniczna dla agenta AI Codex

1. Kontekst aplikacji

Repozytorium: CuteLittleGoat/Nekrolog. Aplikacja jest statyczna: frontend index.html + app.js czyta gotowe pliki JSON, zwłaszcza data/latest.json, data/job.json i data/errors.json.

Odświeżanie danych wykonuje pipeline Node.js, głównie przez:

  • scripts/refresh_static.mjs — główny skrypt odświeżania danych;
  • scripts/nekrolog_core.mjs — logika parserów i wspólne stałe;
  • scripts/normalize.mjs — normalizacja i dopasowanie tekstów;
  • config/sources.json — konfiguracja źródeł;
  • data/latest.json — snapshot danych dla frontendu.

Obecnie aplikacja zna listę wariantów dla osoby Helena Gawin w stałej HELENA_GAWIN_PHRASES. Frontend dodatkowo pokazuje status Helena Gawin na podstawie dopasowań w aktualnych danych.

2. Efekt do zaimplementowania

Po każdym odświeżeniu danych skrypt ma sprawdzić, czy w aktualnym oknie wyników istnieje wpis pasujący do Heleny Gawin. Przez „aktualne okno wyników” rozumie się domyślnie te rekordy, które trafiają do:

  • recent_deaths — ostatnie zgony/wzmianki z okna -7 dni;
  • upcoming_funerals — najbliższe pogrzeby/msze z okna +7 dni.

Jeżeli zostanie znalezione nowe trafienie, którego aplikacja jeszcze nie zgłosiła, skrypt ma wysłać wiadomość na Discord przez URL z: 

process.env.DISCORD_WEBHOOK_URL

Brak zmiennej DISCORD_WEBHOOK_URL nie może psuć działania aplikacji. W takim przypadku skrypt ma pominąć wysyłkę i zapisać w job.json informację, że powiadomienie Discord zostało pominięte z powodu braku sekretu.

3. Wymagane zasady bezpieczeństwa

  • Nie wolno umieścić pełnego webhook URL w żadnym pliku repozytorium.
  • Nie wolno wysyłać webhook URL do frontendu.
  • Nie wolno zapisywać webhook URL w data/latest.json, data/job.json ani data/errors.json.
  • Nie wolno wypisywać webhook URL do logów GitHub Actions.
  • Wiadomość do Discorda ma być wysyłana tylko z procesu Node.js uruchamianego w GitHub Actions.
  • Nie wolno wykonywać wysyłki z app.js ani z kodu przeglądarkowego.

4. Proponowane nowe pliki

Plik Cel Czy wymagany?

5. Plik stanu deduplikacji

Dodać plik data/discord_notified.json. Jeśli go nie ma, skrypt ma utworzyć go automatycznie. Sugerowany format: 

{
  "version": 1,
  "updated_at": "2026-05-08T00:00:00.000Z",
  "sent": {
    "hash_trafienia": {
      "sent_at": "2026-05-08T00:00:00.000Z",
      "name": "Helena Gawin",
      "kind": "funeral",
      "source_id": "example_source",
      "source_name": "Example Source",
      "date_death": null,
      "date_funeral": "2026-05-10",
      "time_funeral": "12:00",
      "url": "https://example.test/wpis"
    }
  }
}

Klucz deduplikacyjny powinien być stabilny. Zalecany skład:

  • kind
  • source_id
  • url, jeśli istnieje
  • name lub full_name
  • date_death
  • date_funeral
  • time_funeral

Z powyższych pól można zbudować string i policzyć hash SHA-256, żeby klucz był krótki i bezpieczny.

6. Szkic modułu scripts/discord_notify.mjs

Poniższy kod jest szkicem wdrożeniowym. Codex może go dostosować do stylu repozytorium, ale powinien zachować opisane zachowanie i testowalność. 

// scripts/discord_notify.mjs
import { readFile, writeFile, mkdir } from "node:fs/promises";
import { createHash } from "node:crypto";

const DEFAULT_STATE_PATH = "data/discord_notified.json";

export function normalizeText(value) {
  return String(value ?? "")
    .normalize("NFKC")
    .replace(/\s+/g, " ")
    .trim();
}

export function makeNotificationKey(row) {
  const raw = [
    "helena-gawin-v1",
    row?.kind ?? "",
    row?.source_id ?? "",
    row?.url ?? "",
    row?.name ?? row?.full_name ?? "",
    row?.date_death ?? "",
    row?.date_funeral ?? "",
    row?.time_funeral ?? ""
  ].map(normalizeText).join("|");

  return createHash("sha256").update(raw, "utf8").digest("hex");
}

export async function readNotificationState(path = DEFAULT_STATE_PATH) {
  try {
    const parsed = JSON.parse(await readFile(path, "utf8"));
    if (parsed && typeof parsed === "object" && parsed.sent && typeof parsed.sent === "object") {
      return parsed;
    }
  } catch {
    // Missing file is normal on first run.
  }
  return { version: 1, sent: {} };
}

export async function writeNotificationState(state, path = DEFAULT_STATE_PATH) {
  await mkdir("data", { recursive: true });
  await writeFile(path, JSON.stringify(state, null, 2) + "\n", "utf8");
}

export function buildDiscordMessage(hits) {
  const first = hits[0] || {};
  const name = first.name || first.full_name || "Helena Gawin";
  const source = first.source_name || "nieznane źródło";

  // Placeholder. Treść docelową użytkownik ustali później.
  return [
    "Aplikacja Nekrolog znalazła wpis pasujący do: Helena Gawin.",
    `Imię/nazwisko w rekordzie: ${name}`,
    `Źródło: ${source}`,
    first.date_funeral ? `Data pogrzebu/mszy: ${first.date_funeral}${first.time_funeral ? " " + first.time_funeral : ""}` : null,
    first.url ? `Link: ${first.url}` : null
  ].filter(Boolean).join("\n");
}

export async function postDiscordWebhook(webhookUrl, content, fetchImpl = globalThis.fetch) {
  if (!webhookUrl) return { ok: false, skipped: true, reason: "missing_webhook_url" };
  if (!fetchImpl) return { ok: false, skipped: false, reason: "fetch_unavailable" };

  const response = await fetchImpl(webhookUrl, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      content,
      allowed_mentions: { parse: [] }
    })
  });

  if (response.ok) return { ok: true, status: response.status };

  let body = "";
  try {
    body = await response.text();
  } catch {
    body = "";
  }

  return {
    ok: false,
    skipped: false,
    status: response.status,
    reason: `discord_http_${response.status}`,
    body: body.slice(0, 500)
  };
}

export async function notifyDiscordForNewHits({
  hits,
  webhookUrl,
  enabled = true,
  statePath = DEFAULT_STATE_PATH,
  now = new Date().toISOString(),
  fetchImpl = globalThis.fetch
}) {
  const safeHits = Array.isArray(hits) ? hits : [];
  const state = await readNotificationState(statePath);

  const hitEntries = safeHits.map((row) => ({ row, key: makeNotificationKey(row) }));
  const newEntries = hitEntries.filter(({ key }) => !state.sent[key]);

  const result = {
    enabled: !!enabled,
    hit_count: safeHits.length,
    new_hit_count: newEntries.length,
    attempted: false,
    sent: false,
    skipped_reason: null,
    error: null
  };

  if (!enabled) {
    result.skipped_reason = "disabled";
    return result;
  }

  if (!webhookUrl) {
    result.skipped_reason = "missing_secret_DISCORD_WEBHOOK_URL";
    return result;
  }

  if (!newEntries.length) {
    result.skipped_reason = "no_new_hits";
    return result;
  }

  result.attempted = true;
  const message = buildDiscordMessage(newEntries.map((entry) => entry.row));
  const post = await postDiscordWebhook(webhookUrl, message, fetchImpl);

  if (!post.ok) {
    result.error = post.reason || "discord_send_failed";
    result.status = post.status ?? null;
    return result;
  }

  for (const { row, key } of newEntries) {
    state.sent[key] = {
      sent_at: now,
      name: row?.name || row?.full_name || null,
      kind: row?.kind || null,
      source_id: row?.source_id || null,
      source_name: row?.source_name || null,
      date_death: row?.date_death || null,
      date_funeral: row?.date_funeral || null,
      time_funeral: row?.time_funeral || null,
      url: row?.url || null
    };
  }

  state.updated_at = now;
  await writeNotificationState(state, statePath);

  result.sent = true;
  result.sent_count = newEntries.length;
  return result;
}

7. Zmiany w scripts/refresh_static.mjs

Po wyliczeniu recent_deaths oraz upcoming_funerals należy:

  1. Zebrać trafienia dla Heleny Gawin.
  2. Wywołać moduł powiadomień Discord.
  3. Dopisać wynik powiadomienia do job.json.
  4. Nie zapisywać sekretu ani pełnego webhook URL w żadnym JSON-ie.
// scripts/refresh_static.mjs — koncepcyjny fragment do wpięcia

import { notifyDiscordForNewHits } from "./discord_notify.mjs";

// ...po utworzeniu recent_deaths i upcoming_funerals:
const helenaHitsForDiscord = [...recent_deaths, ...upcoming_funerals]
  .filter((row) => row?.priority_hit === true || textMatchesAny(
    [row?.name, row?.full_name, row?.note, row?.place, row?.source_name].join(" "),
    phraseVariants
  ));

const discordNotification = await notifyDiscordForNewHits({
  hits: helenaHitsForDiscord,
  webhookUrl: process.env.DISCORD_WEBHOOK_URL,
  enabled: process.env.DISCORD_NOTIFY_ENABLED !== "false"
});

// Potem dopisać discordNotification do job.json.
// Nie wpisywać webhookUrl do latest.json, job.json ani logs.

Wynik powiadomienia w data/job.json

Obiekt job powinien dostać pole: 

"discord_notification": {
  "enabled": true,
  "hit_count": 1,
  "new_hit_count": 1,
  "attempted": true,
  "sent": true,
  "skipped_reason": null,
  "error": null
}

Jeśli sekretu nie ma: 

"discord_notification": {
  "enabled": true,
  "hit_count": 1,
  "new_hit_count": 1,
  "attempted": false,
  "sent": false,
  "skipped_reason": "missing_secret_DISCORD_WEBHOOK_URL",

  "hit_count": 0,

8. Treść wiadomości Discord

Treść docelowa zostanie ustalona później. Na teraz wystarczy placeholder. Ważne, żeby treść była zbudowana w jednej funkcji, na przykład: buildDiscordMessage(hits).

Placeholder może wyglądać tak: 

Aplikacja Nekrolog znalazła wpis pasujący do: Helena Gawin.
Imię/nazwisko w rekordzie: ...
Źródło: ...
Data pogrzebu/mszy: ...
Link: ...

Wysyłka powinna używać prostego payloadu: 

{
  "content": "tekst wiadomości",
  "allowed_mentions": { "parse": [] }
}

allowed_mentions z pustą listą ogranicza ryzyko przypadkowego pingowania ról lub osób, jeśli jakiś tekst ze źródła zawiera znak @.

9. Obsługa błędów

  • Jeśli nie ma webhooka, nie przerywać odświeżania danych.
  • Jeśli Discord zwróci błąd HTTP, nie oznaczać trafienia jako wysłanego.
  • Jeśli Discord zwróci błąd HTTP, zapisać krótki opis w job.discord_notification.error.
  • Nie wpisywać pełnego webhook URL do komunikatu błędu.
  • Nie blokować aktualizacji data/latest.json, jeśli problem dotyczy tylko Discorda.

10. Zmiany w GitHub Actions

Codex powinien najpierw sprawdzić, czy istnieje workflow odświeżający dane. Jeśli istnieje, należy go zmodyfikować. Jeśli nie istnieje, można dodać nowy plik: .github/workflows/refresh.yml.

W workflow trzeba przekazać sekret jako zmienną środowiskową: 

DISCORD_WEBHOOK_URL: ${{ secrets.DISCORD_WEBHOOK_URL }}

Przykładowy workflow, jeśli w repozytorium nie ma jeszcze właściwego: 

name: Refresh Nekrolog data

on:
  workflow_dispatch:
  schedule:
    - cron: "0 */6 * * *"

permissions:
  contents: write

jobs:
  refresh:
    runs-on: ubuntu-latest

    env:
      DISCORD_WEBHOOK_URL: ${{ secrets.DISCORD_WEBHOOK_URL }}
      DISCORD_NOTIFY_ENABLED: "true"

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: "20"
          cache: "npm"

      - name: Install dependencies
        run: npm ci

      - name: Run tests
        run: npm test

      - name: Refresh static JSON
        run: npm run refresh

      - name: Commit refreshed data
        run: |
          git config user.name "github-actions[bot]"
          git config user.email "github-actions[bot]@users.noreply.github.com"
          git add data/latest.json data/job.json data/errors.json data/discord_notified.json config/sources.json
          if git diff --cached --quiet; then
            echo "No data changes to commit."
          else
            git commit -m "Refresh Nekrolog data"
            git push
          fi
Jeśli repozytorium ma już działający workflow publikujący dane, nie zastępować go bezmyślnie. Trzeba tylko dodać DISCORD_WEBHOOK_URL do środowiska kroku npm run refresh oraz upewnić się, że nowy plik data/discord_notified.json jest commitowany razem z danymi.

11. Testy

Dodać testy jednostkowe dla modułu Discord. Testy nie mogą naprawdę wysyłać wiadomości do Discorda. Należy użyć atrapowej funkcji fetch. 

// tests/discord_notify.test.mjs
import test from "node:test";
import assert from "node:assert/strict";
import { mkdtemp, rm } from "node:fs/promises";
import { join } from "node:path";
import { tmpdir } from "node:os";
import {
  makeNotificationKey,
  notifyDiscordForNewHits
} from "../scripts/discord_notify.mjs";

test("makeNotificationKey returns the same key for the same row", () => {
  const row = {
    kind: "funeral",
    source_id: "test",
    name: "Helena Gawin",
    date_funeral: "2026-05-10",
    time_funeral: "12:00",
    url: "https://example.test/1"
  };

  assert.equal(makeNotificationKey(row), makeNotificationKey({ ...row }));
});

test("notifyDiscordForNewHits sends only once for the same hit", async () => {
  const dir = await mkdtemp(join(tmpdir(), "nekrolog-discord-"));
  const statePath = join(dir, "discord_notified.json");

  let callCount = 0;
  const fakeFetch = async () => {
    callCount += 1;
    return { ok: true, status: 204 };
  };

  const hit = {
    kind: "funeral",
    source_id: "test",
    source_name: "Test",
    name: "Helena Gawin",
    date_funeral: "2026-05-10",
    time_funeral: "12:00",
    url: "https://example.test/1"
  };

  const first = await notifyDiscordForNewHits({
    hits: [hit],
    webhookUrl: "https://discord.com/api/webhooks/test/test",
    statePath,
    fetchImpl: fakeFetch
  });

  const second = await notifyDiscordForNewHits({
    hits: [hit],
    webhookUrl: "https://discord.com/api/webhooks/test/test",
    statePath,
    fetchImpl: fakeFetch
  });

  assert.equal(first.sent, true);
  assert.equal(second.sent, false);
  assert.equal(second.skipped_reason, "no_new_hits");
  assert.equal(callCount, 1);

  await rm(dir, { recursive: true, force: true });
});

12. Aktualizacja dokumentacji

Po implementacji warto dodać krótką informację do README.md:

  • powiadomienia Discord są opcjonalne;
  • wymagają sekretu DISCORD_WEBHOOK_URL w GitHub Actions;
  • sekret nie jest potrzebny do lokalnego działania frontendu;
  • brak sekretu nie powinien powodować awarii odświeżania danych.

13. Lokalna praca Codexa

Codex powinien wykonać: 

npm test
npm run refresh

Przy lokalnym uruchomieniu bez DISCORD_WEBHOOK_URL skrypt powinien zakończyć się poprawnie, a w data/job.json powinna pojawić się informacja o pominięciu Discorda.

Kontrola jakości

Kryteria akceptacji

  • Webhook URL jest zapisany tylko jako GitHub Actions Secret DISCORD_WEBHOOK_URL.
  • W publicznych plikach repozytorium nie ma pełnego webhook URL.
  • Frontend app.js nie wysyła niczego do Discorda.
  • scripts/refresh_static.mjs nadal generuje data/latest.json, data/job.json i data/errors.json.
  • Gdy nie ma sekretu, odświeżanie danych nie kończy się błędem.
  • Gdy jest nowe trafienie Helena Gawin, wysyłana jest jedna wiadomość na Discorda.
  • Drugie uruchomienie bez nowego trafienia nie wysyła duplikatu wiadomości.
  • Gdy pojawi się kolejne, inne trafienie, wiadomość wysyła się ponownie.
  • Stan wysłanych powiadomień zapisuje się w data/discord_notified.json.
  • Testy jednostkowe przechodzą przez npm test.
  • Workflow GitHub Actions ma dostęp do sekretu przez secrets.DISCORD_WEBHOOK_URL.
  • Workflow commituje data/discord_notified.json, żeby deduplikacja działała między uruchomieniami.
